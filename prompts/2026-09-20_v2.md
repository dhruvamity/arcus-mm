## 5. WS-2/3 — One engine (`src/sim/engine.py`)

### 5.1 Architecture
`SimEngine(markets, strategies, fill_models, cost_model, latency_model, clock)` consumes a single time-ordered stream of events `{BBO, L2_DELTA, TRADE, FUNDING, ORACLE/MARK, CLOCK_TICK}` and emits fills/orders logs. Backtest replays recorded files into it; the live paper trader feeds live frames into the **same** object; testnet adapters later implement the same strategy interface. No strategy or accounting code exists outside the engine.

### 5.2 Order lifecycle (per side)
- Strategy emits target quotes at decision time `t`. Engine schedules **place/modify/cancel** arrival at `t + sample(place|modify|cancel latency)` drawn per order from the **empirical measured distribution** (seeded RNG; seed in the run manifest). Include feed latency separately.
- Old quote stays live until the cancel/modify **arrives** (pick-off risk). New quote rests only after arrival.
- On arrival, if an ALO quote would cross the *book at arrival time* → simulate `POST_ONLY_WOULD_CROSS` (count it; strategy sees the rejection).
- ALO orders and cancels skip the 50 ms taker bump; taker/IOC flatten orders are delayed 50 ms + sampled latency and pay 2.25 bps. (Keep the flags in `venue_verified.yaml` as `[DOCS_ONLY]` until testnet proves them.)
- Enforce per market at creation: tick alignment, step alignment, `minOrderSize`, `minOrderNotional`, `maxOrderSize`; invalid orders are rejected and counted. `min_clip = max(minOrderNotional, minOrderSize × price)` is computed from live `/v1/markets`, not hard-coded.

### 5.3 Fill models
- **A** touch=fill (diagnostic). **B** queue-aware: queue-ahead = displayed L2 size at our price at arrival (not just BBO size); depleted by trades at that price; optional pre-declared sensitivity where a fraction *c ∈ {0, 0.5}* of L2 size decreases at our level not explained by trades counts as cancels ahead. **C** strict trade-through (price strictly beyond ours).
- Report **B as the central estimate and C as the robustness floor**. Keep C as the gate, but also report N_B and N_C; when N_C < threshold the best possible label is `INSUFFICIENT DATA` (never a positive label).
- Trade side: define `aggressor` from the recorded data (see WS-1 test) and assert the engine's convention against it.

### 5.4 Costs, risk, accounting
- Maker 0 bps; taker 2.25 bps on any taker fill (forced flatten, stop-out). Funding per R-10. Mark-to-mid for PnL, mark price where the venue docs require it for margin/liquidation checks.
- Order/cancel pools per docs: place=1 order unit, cancel=1 cancel unit, modify=1 **order** unit, cancelAll=1000 cancel units, +1 unit per $0.10 filled notional (both pools), 1 action/10 s drip at zero. Log pool low-water marks.
- Risk manager (state machine, unit-tested): inventory cap in clips; over cap → reduce-only passive unwind, then taker flatten after a pre-declared timeout; stale BBO > 3 s (checked on every clock tick, ≤ 250 ms period) → cancel all + pause until N clean updates; crossed book, sequence gap, price-band proximity, daily-loss limit → cancel all + flatten. Quoting is impossible while any kill state is active.
- Regime tags: attach `{dow_class, session, underlying_open, event_window}` to every event/fill using the event's own timestamp. Event-window pauses apply to equity/ETF/commodity/index perps by default; a crypto pause is an explicit A/B parameter, default off.

### 5.5 Strategies (all in one process, paired on the same event stream)
`DoNothing`, `RandomSide` (baseline), `FixedSpread`, `VolClock` (EWMA σ), `AvellanedaStoikov` (unit-consistent, calibrated), `Adaptive` (microprice/OFI + inventory lean). Quote relative to the **live book** (join/improve/behind) as an explicit parameter; log distance-to-touch in ticks for each quote. Pre-declare the parameter grid (≤ 12 configs total) in `research/prereg_backtest.md` before running it.

### 5.6 Tests (all offline, deterministic; commit outputs to `evidence/`)
1. Scripted scenarios with hand-computed expectations (fills, cash, position, fees, funding, DD) for A, B, C.
2. A ≥ B ≥ C monotonicity on the *same* full path, including fills, and PnL per fill difference explained.
3. Cancel-latency pick-off: a stale quote is filled during cancel latency.
4. `POST_ONLY_WOULD_CROSS` on stale pricing.
5. Queue: L2-informed queue-ahead, FIFO depletion, modify priority rules.
6. Quantisation & min-size: sub-minimum orders rejected.
7. Funding across two hourly boundaries; off-hours fixed-rate rule.
8. Lookahead: shifting trade timestamps earlier than the quote arrival changes fills; a trade before arrival never fills.
9. Causality of EWMA volatility (value at t independent of data after t).
10. Kill-switch state machines (stale, crossed, gap, inventory, loss) each block quoting.
11. Determinism: identical input + seed ⇒ identical **fill log hash** produced by the real engine.
12. **Replay parity**: run the live-paper code path on a recorded raw session and compare to the replay engine output — exact match.
13. `scripts/mutation_check.py`: ≥ 8 mutations must each fail ≥ 1 test.
