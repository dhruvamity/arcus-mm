## 9. WS-D — One engine (`src/sim/engine.py`, tag `v0.3.0`)

**9.1 Architecture.** `SimEngine` consumes one time-ordered stream of `{BBO, L2_DELTA, TRADE, FUNDING, MARK, CLOCK_TICK}` events. One canonical loader (`src/data/loader.py`) turns recorded raw / compressed files into that stream for replay; the live paper trader feeds the *same* event objects; testnet adapters later use the same strategy interface. Merge order: `recv_ts_ns`, stable tie-break by file offset, verified per market (BBO `lastSequenceId` non-decreasing). **Every engine input, including `CLOCK_TICK`, is persisted as an event** so replay consumes exactly what the live run saw. In replay the engine synthesizes ticks between events at ≤ 100 ms of event time.

**9.2 L2 (fix V-06, V-07).** Use `LocalOrderBook.apply_snapshot / apply_delta`. Queue-ahead = displayed L2 size at our price **at arrival time** (not decision time, not BBO size). Quotes behind the touch inherit the real queue at their price. Optional pre-declared sensitivity: a fraction c ∈ {0, 0.5} of L2 size decreases at our level not explained by trades counts as cancels ahead. Handle the Arcus splice rule (first delta may be several sequences ahead; mid-stream gap ⇒ invalidate, wait for snapshot; repeated price in a frame ⇒ last write wins).

**9.3 Independent worlds (fix V-12).** Each (strategy, fill model) is its own simulation with its own inventory, resting orders and pools, all fed by the same events. Add a separate, clearly named `paired_common_quotes` diagnostic mode (today's behaviour) used only for monotonicity checks. Gates use the independent Model C world.

**9.4 Latency (fix V-11).** `LatencyModel.sample(action)` with implementations `Constant` and `Empirical(samples_file)`; place, modify, cancel and feed latencies are sampled separately, per order, seeded, with the seed and the latency-file hash in the run manifest. Order-path latency cannot be measured without testnet, so until it is: label all latency `PROVISIONAL`, and run a pre-declared scenario grid (place/cancel = 25, 60, 150, 300, 700 ms; +500 ms stress). The pre-registration must name which scenario is gating. Never print "empirical" for a constant.

**9.5 Rate limits (fix V-10).** One pool set per **subaccount**, shared by every market and strategy instance in a run. Enforce before every action: place = 1 order unit, modify = 1 order unit, cancel = 1 cancel unit, cancelAll = 1,000 cancel units, +1 unit per $0.10 filled notional (both pools), 1 action / 10 s drip at zero. A denied action is visible to the strategy (`RATE_LIMITED`) and skipped. Log low-water marks. Use modify (not cancel + place) where the venue allows same-price size decreases to keep priority.

**9.6 Risk manager (fix V-09).** Per (market, strategy) state machine with **recovery**: `NORMAL → PAUSED_STALE_FEED | PAUSED_GAP | FLATTENED_CROSSED_BOOK | REDUCE_ONLY | FLATTENED_LOSS_LIMIT → NORMAL` after pre-declared conditions (e.g. book valid and ≥ N = 20 clean BBO updates over ≥ 5 s). Enforce: inventory cap in clips (over cap ⇒ reduce-only passive unwind, then taker flatten after a pre-declared timeout at bid/ask ∓ slippage + 2.25 bps); stale BBO > 3 s (checked on every tick, ≤ 250 ms period); crossed book; sequence gap; price-band proximity; daily-loss limit ⇒ cancel all + flatten. Kill states are scoped to the affected market only. Quoting is impossible while any kill state is active. Cancel-all uses cancel latency (no instant cancels).

**9.7 Funding and marks (fix V-08, V-14).** Settle funding at each hourly funding timestamp on position × mark using recorded **realized** rates (REST `/v1/fundingRates` snapshots); non-crypto perps use the fixed off-hours rate per the venue config. Parse `predictedFunding` with the correct field (`rate1h`) only as an *estimate* for live display. Track a mark price for margin checks and report PnL marked to mid *and* to mark. Model off-hours price bands and higher initial margin for equity / ETF / commodity perps.

**9.8 Tests (offline, deterministic; commit outputs to evidence).**
1. Scripted scenarios with hand-computed expectations for A, B, C (fills, cash, position, fees, funding, drawdown).
2. Randomized invariants over ≥ 200 seeds: paired-mode A ≥ B ≥ C; balance-sheet identity; no fill before arrival; pools never negative; inventory cap never exceeded except during flatten.
3. Cancel-latency pick-off; post-only rejection at arrival; `SELF_TRADE` handling.
4. **L2 tests:** a snapshot + delta sequence with a large queue at our price ⇒ Model B does not fill until that queue is consumed; quote behind the touch inherits queue; gap ⇒ invalidate ⇒ resync ⇒ risk state recovers.
5. **Funding regression:** 60 `predictedFunding` messages in one hour do **not** change PnL; two hourly settlements charge exactly two hours; off-hours fixed rate applied.
6. **Risk recovery:** every pause state returns to NORMAL under its declared condition; a pause on market X does not pause market Y.
7. Rate-limit enforcement, drip, cancelAll = 1,000, shared pools across markets.
8. Lookahead: shifting a trade earlier than arrival changes fills; a trade before arrival never fills.
9. Causality of EWMA volatility with a real assertion (value at t unchanged when later data is altered).

## 10. WS-E — Strategies and candidate families

Every strategy — baselines and candidates — goes through the *identical* pipeline (event-driven replay on `SimEngine`, all three fill models as independent worlds, base-tier fees, funding, subaccount pools, latency scenario grid, out-of-sample + walk-forward, stress). Nothing is presumed profitable; a failing candidate is reported `NOT VALIDATED` with numbers.

1. **Baselines:** `DoNothing`, `RandomSide`, `FixedSpread`. Quote relative to the **live book** (join / improve / behind) as an explicit parameter and log distance-to-touch in ticks.
2. **Avellaneda–Stoikov:** total spread δ = γσ²T + (2/γ)·ln(1+γ/κ) is the *total* spread (bid = r − δ/2, ask = r + δ/2); a perp has no terminal time, so use a pre-declared rolling horizon H (or the infinite-horizon form); fit κ from recorded fill intensity λ(δ) = A·e^(−κδ) versus distance from mid. If the calibrated spread falls outside a plausible band around the market's typical spread, report `NOT TUNABLE` and drop it from OOS (today it has 0 fills on all 20 markets).
3. **Candidate families (tune-week exploration; at most 12 configs total enter pre-registration):**
   - **C1 Selective quoting (primary hypothesis).** Quote only when the estimated net edge is positive: spread ≥ 2 × maker fee + conditional adverse selection + buffer, low volatility, no recent jump, balanced book; thresholds estimated on development data only. Markets: long-tail crypto / single-stock / ETF perps ranked by the scanner (including newly listed markets recorded from listing time); BTC/ETH as benchmarks. Queue tactics to test: improve by one tick when the spread is wide; join a level right after it forms; avoid reprice churn (only same-price size decreases keep priority). *Kill:* no market/state bucket keeps positive net edge from development to validation data.
   - **C2 Oracle-lead filter** (modifier on any strategy): widen or pull quotes when the oracle moves ahead of Arcus mid by > x bps. *Kill:* no measurable oracle lead at 100 ms–5 s, or the filter removes more good fills than bad ones.
   - **C3 Off-hours equity / ETF quoting:** wider quotes while the underlying is closed; flatten before the reopen and around scheduled events; model higher off-hours initial margin, price bands, and the mark price. *Kill:* reopen gaps or band trapping cost more than the spread captured, or capital fit fails.
   - **C4 Signal-conditioned one-sided maker:** quote only the side favoured by imbalance / microprice; exit passively at +1 tick or by time stop. *Kill:* the signal does not beat a shuffled-signal control out of sample.
   - Funding note: crypto base funding is 0.01 % per 8 h (≈ 0.125 bp/h) and RWA base is SOFR + 0.5 % per year, so on seconds-to-minutes inventory horizons funding is a cost line, not a strategy.
4. **Selection rule (pre-declared, single):** per (market, strategy), the config that maximizes tune-week Model-C net bps per fill subject to N ≥ 30 fills; ties → smaller spread. This rule defines the multiple-testing family.
5. Strategies receive rejections (`POST_ONLY_WOULD_CROSS`, `RATE_LIMITED`) and pool state.

## Appendix C — Venue facts to re-verify with `arcus-docs` before relying on them

- **L2:** `l2OrderbookUpdates` = snapshot + deltas with a per-market, monotonically increasing `lastSequenceId`; the first delta after a snapshot may be several sequences ahead (do not require snapshot+1); a mid-stream gap is real; a delta frame may list the same price more than once (apply in order, last write wins). `l2Orderbook` = periodic full snapshots (~200 ms). Frame envelope in our recordings: `{session_id, recv_ts_ns, market, channel, type, data:{…, contents:{…, lastSequenceId, globalSequenceId, timestamp(µs)}}}`.
- **Trades:** no snapshot on subscribe (a disconnect leaves an unrecoverable hole unless REST backfills); fills of one taker order share `takerOrderId`, timestamp and `sequenceNumber`. **BBO:** carries `lastSequenceId`, `globalSequenceId`, `timestamp`.
- **Funding:** charged hourly; crypto base 0.01 % per 8 h; RWA base SOFR + 0.5 % per year; `predictedFunding` payload is `{market, rate1h}`. **Off-hours (equity / ETF / commodity / index perps):** fixed funding, higher initial margin for opening or growing positions, dynamic price bands, mark = 2.5-min EWMA of the book impact mid bounded by the bands.
- **Rate limits:** IP bucket 1,500 weight, refill 25/s; per-subaccount pools 20,000 order / 40,000 cancel units, +1 unit per $0.10 filled notional, 1 action / 10 s drip when empty, `cancelAllOrders` = 1,000 cancel units, modify charged to the order pool. **WebSocket:** 24 h connection lifetime, 100 subscriptions per connection, 1,000 per IP, 50 new connections / min.
- **Orders:** every order needs `goodTilTime` (≥ 1 month ahead); `ALO` (post-only) rejects with `POST_ONLY_WOULD_CROSS`; `SELF_TRADE` rejection exists; a modify is cancel + place — only a same-price size decrease keeps queue priority; `scheduleCancel` dead-man's switch: lead 5 s–5 min, 10 auto-fires per UTC day per subaccount.
- **Fees (from the repo YAML, tagged `[VERIFIED_API]` — re-check `/v1/feeTiers`):** base tier maker 0 bps, taker 2.25 bps; min order notional $5.
- **Availability:** the venue's disclaimer says it is not available in the US, Canada, the UK and other restricted jurisdictions; never suggest circumventing geo-restrictions.
